## 已完成的真实结构映射

在**代码已提交且工作区干净**时运行：

```powershell
python -m bioinformatics.m2_pf00741 structure `
  --hmm data/raw/pfam_m2_20260923/PF00741.hmm `
  --hmm-receipt data/raw/pfam_m2_20260923/download_receipt.json `
  --pdb data/raw/structure_m2_20260923/7R1C.pdb `
  --pdb-receipt data/raw/structure_m2_20260923/7R1C_download_receipt.json `
  --chain N --threads 1 `
  --out-dir data/processed/m2_c/7r1c_001 `
  --summary results/bioinformatics/structure_7r1c_summary.json
```

真实结果有 88 个 `SEQRES` 提交序列位置，65 个位置含实验建模的 CA 原子，23 个未建模；39 个位置与 PF00741 HMM 对齐，覆盖 39 个不同 match state。逐残基表为 `data/processed/m2_c/7r1c_001/7r1c_residue_hmm_map.csv`，它有 88 行，明确标出未建模、未进入 HMM 局部比对、HMM 插入及二级结构。只有实际建模的残基才填 PDB 作者残基编号和二级结构。小型可入库摘要见 `results/bioinformatics/structure_7r1c_summary.json`，包含代码提交、来源和逐表哈希。未建模残基不代表其功能或实际构象已测定。

## B 数据交接后的正式扫描命令

B 的最新复现报告称处理结果在本地 `data/processed/gvpa_v1_reproduction/`，但公共 Git 只含数字和哈希；当前 C 工作区未收到下列实际文件。先将 B 的完整交接目录放在可读取的位置，核对目录层级后运行：

```powershell
python -m bioinformatics.m2_pf00741 scan `
  --metadata data/processed/gvpa_v1_reproduction/metadata.csv `
  --fasta data/processed/gvpa_v1_reproduction/sequences_for_clustering.fasta `
  --split-manifest data/processed/gvpa_v1_reproduction/split/split_manifest.csv `
  --audit-summary results/data_audit/gvpa_v1_audit_summary.json `
  --split-summary results/data_audit/gvpa_v1_split_summary.json `
  --hmm data/raw/pfam_m2_20260923/PF00741.hmm `
  --hmm-receipt data/raw/pfam_m2_20260923/download_receipt.json `
  --threads 1 --boundary-bits 2 `
  --out-dir data/processed/m2_c/pf00741_scan_001 `
  --scan-summary results/bioinformatics/pf00741_scan_summary.json `
  --coordinate-summary results/bioinformatics/hmm_coordinate_summary.json
```

如果 B 的实际 split 文件路径不同，仅调整 `--split-manifest`。程序检查：冻结摘要本身的 SHA-256、metadata/FASTA/split 的冻结 SHA-256、2078 条候选中恰好 2076 条 QC 合格、内部 ID 与完整序列哈希一一对应、discovery 1453/335 簇、validation 623/143 簇、primary 数量，以及零跨集簇泄漏。不满足时在扫描前拒绝执行。

使用模型的 **GA 25/25 bits** 作为家族命中条件，并另做 `T=0/domT=0` 的宽松搜索，仅用于记录弱命中和距离 GA 2 bits 内的边界记录。所有 2076 条序列必须有 `accepted`、`multi_hit`、`boundary`、`weak_hit`、`no_hit` 或 `failed` 状态。保留全部 GA 接受域、插入位原始位置、缺失 HMM state、域覆盖和 HMM 覆盖；插入位的 `hmm_match_state` 留空。`no_hit` 仅指该搜索规则下未检出，不能填作功能阴性。`failed` 会保留原因，不能计入成功覆盖。

原始命中与逐残基表保存在被忽略的 `data/processed/`；两个小型摘要分别统计 discovery 和 validation 的扫描状态/覆盖，均不计算 validation 保守性。若出现失败或需复核的边界状态，报告中逐项说明；不要把 validation 用于 M3 候选区选择。`FAILED.txt` 表示运行不完整，成功摘要不应存在。新运行应换新的输出目录和实验编号，不能覆盖旧结果。
